# 🏛️ Система учета и обработки обращений граждан

Веб-приложение для автоматизации процесса подачи, распределения и аналитики обращений граждан в государственные ведомства. Проект построен на базе микросервисной архитектуры с разделением на независимый бэкенд (Go), фронтенд (React) и базу данных (MySQL), оркеструемых через Docker Compose.

---

## 🛠️ Технологический стек

### Бэкенд (Backend)

* **Язык разработки:** Go 1.26
* **Веб-фреймворк:** Iris v12 (высокопроизводительный HTTP-движок)
* **Аутентификация:** JWT (JSON Web Tokens) с разделением ролей (*citizen* / *employee*)
* **Безопасность:** Хеширование паролей с помощью Bcrypt, минимизированные контейнеры

### Фронтенд (Frontend)

* **Библиотека интерфейса:** React (Vite)
* **Маршрутизация:** React Router (SPA)
* **Сервер раздачи статики:** Nginx (с кастомным роутингом под SPA)

### База данных и DevOps

* **СУБД:** MySQL 8.4 (реляционная база данных)
* **Оркестрация:** Docker / Docker Compose
* **Автоматизация:** GNU Make (Кроссплатформенный Makefile)

## 🚀 Быстрый запуск

### Требования к окружению

Для запуска проекта на локальной машине необходимы:

1. **Docker Desktop** (включая Docker Compose)
2. **GNU Make** (для Windows 11 устанавливается через `winget install ezwinports.make`)

### Запуск системы одной командой

Склонируйте репозиторий, перейдите в корневую папку и выполните:

```bash
make up

```

Команда автоматически соберет Docker-образы для фронтенда и бэкенда, поднимет контейнер базы данных, дождется его полной готовности (`healthcheck`) и инициализирует схему данных вместе с тестовыми пользователями.

## 🕹️ Управление проектом (Команды Make)

В корне проекта настроен `Makefile` для быстрой работы с контейнерами без необходимости ввода длинных консольных команд:

* `make up` — Собрать и запустить все сервисы в фоновом режиме (приложение доступно на порту `80`).
* `make ps` — Проверить статус запущенных контейнеров и проброшенные порты.
* `make logs` — Просмотр логов всех сервисов в реальном времени (выход по `Ctrl + C`).
* `make restart` — Быстрый перезапуск всех модулей системы.
* `make build` — Принудительно пересобрать образы фронтенда и бэкенда без использования кэша.
* `make down` — Остановить работу приложения и погасить контейнеры.
* `make clean` — Полная очистка системы: удаляет контейнеры, внутренние сети и **сбрасывает базу данных** до начального состояния (удаляет volume).

## 📊 Архитектурные особенности проекта

1. **Безопасность (CVE Mitigation):** В рантайм-образах Docker используется автоматический апгрейд пакетов (`apk upgrade`), что снижает количество критических уязвимостей в системных библиотеках до нуля.
2. **SPA Routing на Nginx:** Конфигурация веб-сервера фронтенда перехватывает запросы к несуществующим роутам (`try_files`) и перенаправляет их на `index.html`, исключая появление ошибок `404 Not Found` при обновлении страниц в браузере.
3. **Оптимизация БД:** На уровне СУБД спроектированы B-Tree индексы для составных выборок (по статусам, датам создания и дедлайнам), обеспечивая высокую скорость фильтрации при росте объема данных.
